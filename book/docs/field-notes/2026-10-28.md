## The idea behind it

**Idea (compare on the same stars):** two searches can only be compared where they looked at the same stars with the same kind of data. Before planning a benchmark, count the stars both sides share. Ours shares 30.

**Idea (an open licence is a rule about code, not about ideas):** a licence such as GPL-3.0 controls copying and sharing the code. Running a program on your data, and reading the method in its paper to write your own version, are different acts from pasting its code into yours. When a licence matters, say which of these you are doing.

**Idea (a paper and its code can disagree):** a paper tells you what the authors say they did, the code tells you what runs. When a result is going to be a benchmark, read the code too.

**Idea (fast for whose problem?):** a tool's speed matters only against the size of your own job. VARnet's speed answers a sky-wide job of hundreds of millions of sources. Ours is 549 stars, so a faster engine would save minutes, while a better test of what we miss could change what we find.

**Idea (a benchmark needs an answer key):** a test of a planet finder needs planets whose answer is known. Only six of ours are known, and one of those is shared with them, so a fair test will need extra known cases and injected fake planets.

## What we found, and what we did not

- **Found (VERIFIED):** the paper's sample numbers match the paper and the table in the code. The licence is GPL-3.0. The overlap is 30 stars, and Kepler-1647 is the one shared known host.
- **Found (LIKELY):** the code and the paper differ on how the shapes are compared; the licence advice above.
- **Found (UNCERTAIN):** in the paper's numbers, real light curves gave about 2.3 times as many raw events as upside-down ones, while ours gave fewer real than upside-down. That is my own arithmetic and I do not know the reason yet. Running both on the 30 shared stars would test it.
- **Found (VERIFIED, from the papers):** VarWISE uses infrared NEOWISE data with epochs about six months apart, has no planet class (its two eclipsing classes are Algol-type and W UMa-type), and reports no completeness. Its authors say so: completeness is not quantified. Sampled objects labelled eclipsing-detached were 100% eclipsing (262 checked by eye). VARnet reports no false-alarm rate, only precision and recall on 231 curated objects. No code release was found for either.
- **Found (LIKELY):** a learning-based search for our job would need many labelled planets to learn from. We have six known hosts, and the professional team tested 14. So it would have to train on fake planets only, as VARnet did, and check on a handful of real ones.
- **Not tested:** we did not install or run mono-cbp, and nobody has compared its results with ours. The last 59,000 characters of the VarWISE paper were not read. The decision between improving ours, benchmarking theirs, or building a learning-based search is recommended in pass 3 but not made: it is yours.

## Questions

??? quiz "1. Why did we count shared stars before planning a benchmark?"
    A comparison is only fair where both searches looked at the same stars with the same data. With 30 shared stars, the test is small, and that shapes what we can conclude.

??? quiz "2. Running a GPL program on your data is not the same as copying its code into yours. Why does that matter for our licence plan?"
    The share-alike rule bites when code is combined into another program. Running their tool separately and citing it keeps our own code free to be MIT. This is likely but not legal advice.

??? quiz "3. A tool takes about 50 millionths of a second per star. Why does that not make it the better choice for 549 stars?"
    Speed matters against the size of the job. Ours already finishes in about 40 minutes, so the limit on what we find is how well we test and vet events, not how fast we compute.

??? quiz "4. A paper says one method, the code uses another. What do you do before building a benchmark?"
    Read the code too, then decide whether you are testing the paper's method or the repository's. The two can give different numbers.
